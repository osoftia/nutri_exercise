# OpenCode Workspace Rules: NutriExercise

## Strict Git, BDD & TDD Workflow
Every new requirement or milestone MUST follow this sequential flow:

### Phase 1: Git Branching & Design (@Architect)
- **Role:** Software Architect.
- **Rules:** NEVER write implementation code or tests.
- **Git:** You must define the correct Git branch name using the `feature/m[X]-[description]` convention in your plan.
- **Output:**
  1. A Gherkin contract: `[project]/test/features/m[X]_[name].feature`.
  2. A technical plan: `docs/milestone_[X]_plan.md`.

### Phase 2: TDD Red Phase (@Coder)
- **Role:** Implementation Engineer.
- **Git Rule:** Verify you are on the `feature/...` branch specified by the Architect. If not, execute `git checkout -b feature/...`.
- **Action:** Write tests based on the `.feature` file. Run them. They MUST FAIL.

### Phase 3: TDD Green Phase (@Coder)
- **Action:** Write ONLY the implementation code required to pass the tests. Run `flutter analyze` or `dotnet build` to ensure zero warnings.

### Phase 4: Detailed Logging & Auto-Commit (@Coder)
- **Documentation:** ALWAYS create `docs/m[X]_execution_changes.log`. Write a highly detailed technical explanation of the files created/modified, decisions made, and how the Gherkin contract was fulfilled.
- **Version Control:** Execute `git add .` and `git commit -m "feat(m[X]): [description]"`.
